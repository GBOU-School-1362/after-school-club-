# Обновление каталога

Две инструкции: короткая для школы, подробная для того, кто ведёт репозиторий.

---

## Для сотрудника школы

Каталог собирается из вашей рабочей таблицы. Отдельно ничего заполнять не нужно — ведите её как обычно.

### Чтобы обновить сайт

1. Откройте репозиторий, зайдите в папку `data`.
2. Перетащите новую версию файла на страницу. Имя должно остаться прежним.
3. Внизу нажмите **Commit changes**.
4. Через несколько минут появится запрос на обновление. Его проверит и подтвердит ответственный за сайт.

Всё. Сайт обновится сам.

### Что стоит держать в порядке

**Колонка «Код на mos.ru»** — от неё зависит кнопка записи. Сейчас она пустая у 50 кружков, и на сайте у них вместо кнопки написано «Запись через приёмную школы». Для ГПД и присмотра это правильно, для остальных — нет.

**Колонка «Возраст детей»** превращает «6-8» в дату. Чтобы это прекратилось: выделите колонку, Формат ячеек → Числа → Текст, введите значения заново.

**Направленность** пишите одинаково. Сейчас в файле встречаются «Естествено-научная» и «Социально-гумонитарная» с опечатками — проще выбирать из выпадающего списка, чем набирать руками.

**Время занятий** — через двоеточие: `13:40-14:25`. Запятая и точка тоже понимаются, но лучше единообразно.

После каждой сборки обновляется файл `report.txt` — там перечислено, в какой строке какого листа что не разобралось. Это удобный список для правки.

### Чего в таблице быть не должно

Телефонов педагогов. Публикация ФИО вместе с личным номером требует отдельного письменного согласия сотрудника. Сборка такие поля вырезает и предупреждает, но лучше их не вносить. Подробнее — [PRIVACY.md](PRIVACY.md).

## Для ответственного за репозиторий

### Ручной прогон

```bash
uv run build_catalog.py data/catalog.ods --strict
git diff --stat courses.json
```

`--strict` возвращает ненулевой код при нарушении порогов. Без него файлы всё равно пишутся — удобно, когда разбираешься с новой структурой.

### Что проверять в диффе

Дифф `courses.json` — основной инструмент контроля. Смотрите на:

- **Резкое изменение количества.** Пороги ловят выход за 150–260, но и скачок на 20 внутри диапазона стоит объяснить.
- **Массовое изменение цен.** Если поменялись все 195 — вероятно, поехала колонка.
- **Исчезнувшие коды mos.ru.** Кружок был с кнопкой, стал без — скорее всего, случайно затёрли ячейку.
- **Новые значения `area`.** Появление незнакомой направленности означает либо новую категорию, либо новую опечатку.

### Пороги

Настраиваются в `config.json` → `thresholds`. Сборка падает, если:

- кружков меньше 150 или больше 260
- у более чем 35% нет кода mos.ru
- в `config.json` остались адреса-заглушки `УТОЧНИТЬ`
- в поле педагога найден телефон
- один код mos.ru встречается дважды

Смысл порогов не в точности цифр, а в том, чтобы сломанная выгрузка не уехала на прод молча. Пустой файл или сдвинутые колонки дают резкое отклонение, и сборка останавливается.

### Автоматизация

`.github/workflows/build.yml` запускается при изменении `data/*.ods` или `overrides.json`, собирает каталог в строгом режиме и открывает Pull Request с обновлённым `courses.json`.

Прямой коммит в `main` намеренно не используется: автомат, который молча перезаписывает данные, однажды выложит пустой каталог.

### Годовой цикл

В начале учебного года таблица меняет имя (`Внебюджет_27-28.ods`) и колонки цен (`Стоимость 26-27`, `Стоимость 27-28`). Что нужно поправить:

1. Путь к файлу в workflow и README.
2. Имена колонок цен в `build_catalog.py` — они захардкожены в вызове `col(row, "Стоимость 26-27")`.
3. Проверить, не появились ли новые листы: конвертер о них предупредит в отчёте.

Это единственное место, где ежегодно требуется правка кода. Можно вынести в `config.json`, если надоест.
