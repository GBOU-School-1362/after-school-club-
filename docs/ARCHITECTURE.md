# Каталог кружков: архитектура

Основано на разборе `Внебюджет_26-27.ods` (195 кружков, 6 зданий, учебный год 26–27).

## Что показал файл

| | |
|---|---|
| Кружков | 195 |
| Зданий | 5 школьных корпусов + 5 садов |
| Педагогов | 91 (только «Фамилия И.О.», телефонов нет) |
| С кодом mos.ru | 144 из 195 |
| С расписанием | 154 из 195 |
| Подорожало к 26–27 | 157 |

Таблица — рабочий инструмент планирования, а не источник для публикации. Она содержит номера помещений, часы нагрузки и заготовку финансового свода. Каталог должен брать оттуда подмножество, а не всё подряд.

## Главное решение: таблица остаётся источником

Не переносите данные в отдельную БД с админкой. Завуч продолжает вести тот же `.ods`, потому что он ей нужен и для других целей — тарификации, занятости залов, свода по оплате. Любая параллельная система немедленно разойдётся с таблицей, и поддерживать будут таблицу, а не ваш каталог.

```
Внебюджет_26-27.ods            ведёт завуч, как и раньше
        │
        │  build_catalog.py     чинит, валидирует, отсекает лишнее
        ▼
courses.json + report.txt       машинный слой
        │
        ├── overrides.json      редакторские правки, живут отдельно
        ▼
index.html                      статика, фильтрация в браузере
```

## Слой 1: конвертер

`build_catalog.py` в корне репозитория. Что он делает и почему именно так.

**Читает по именам колонок, не по позициям.** Структура листов не совпадает: у `БЖ9` вставлена «Дата проведения последнего занятия», у `САДЫ` — «Адрес здания», и нет «Кол-во раз в неделю». Заголовки написаны по-разному: `Номерпомещения` и `Номер помещения`, `Стоимость25-26` и `Стоимость 25-26`. Ключ нормализуется — пробелы убираются, регистр приводится.

**Восстанавливает возраст.** LibreOffice превратил 136 значений вида «6-8» в даты (`2026-08-06`). Разбираем обратно: день — нижняя граница, месяц — верхняя. Проверено: перевёрнутых пар нет ни одной. Уцелели строками только диапазоны, где число больше 12 — «8-17», «6-50».

Годы в этих датах — 2023, 2024, 2025, 2026. Файл копируется из года в год, порча накапливается. **Исправьте в источнике:** выделить колонку → Формат ячеек → Текст. Иначе через два года часть диапазонов станет неотличима от настоящих дат.

**Сводит направленности.** В файле 11 написаний для 6 категорий, включая опечатки «Естествено-научная» и «Социально-гумонитарная». Словарь `AREAS` в конвертере приводит к канону; незнакомое значение не выбрасывается, а попадает в отчёт.

**Расклеивает названия.** 60 записей вида `Школьный спортивный клуб «Ермак»Баскетбол "Баланс"` — префикс объединённой ячейки прилип без разделителя. Выносится в отдельное поле `club`.

**Приводит время.** `13.40-14.25`, `19,00-20,30`, две пары в одной ячейке — всё к массиву `["13:40–14:25"]`.

**Не доверяет колонке «Ссылка на кружок», но проверяет через неё код.** Она заполнена ровно один раз, сокращателем `clck.su`. Разворачивание показало: реальная карточка — `card/919834`, а «Код на mos.ru» в той же строке — `2493326`. Код ≠ id карточки, они не связаны напрямую. Ссылка `mos.ru/pgu2/activity/card/{код}` (так было раньше) ведёт не туда почти всегда. Рабочий вариант — поисковый: `mos.ru/pgu2/activity/groups?keyword={код}`.

**Пишет `report.txt`.** 110 замечаний с указанием листа и строки. Это не ошибки конвертера, это состояние данных — список того, что завучу стоит поправить.

## Слой 2: редакторские правки

`overrides.json`, ключ — код mos.ru. Накладывается поверх импорта.

```json
{
  "2493326": {
    "description": "Игровая подготовка, работа в парах, участие в школьной лиге.",
    "image": "images/basketball.jpg"
  }
}
```

Правило жёсткое: **импорт никогда не пишет в overrides, overrides никогда не пишет в courses.json.** Как только описания начнут храниться вместе с импортируемыми полями, следующая синхронизация их сотрёт. Это ровно та ошибка, на которой строятся все «а почему тексты пропали».

## Слой 3: сайт

Статика: `index.html` + `courses.json`. Фильтрация в браузере — 195 записей это ~120 КБ JSON, быстрее любого сервера.

Что добавить к базовому шаблону под эту специфику:

**Фильтр по зданию** — обязателен. Пять корпусов и пять садов, родителю нужен свой. Коды `Т47`, `ИШ60` в интерфейс не выводить, только адреса; секция `buildings` в `config.json` под это и сделана, её нужно заполнить.

**Раздельные каталоги для садов и школы.** У `САДЫ` возраст 2–7, у корпусов 6–18, и 20 позиций «Присмотр и уход» — это не кружок. Смешивать их в одной выдаче — гарантированная путаница. Либо переключатель вверху, либо два раздела.

**Цена за месяц, не за занятие.** В файле «Стоимость 25-26» и «Стоимость 26-27» — это месячная сумма. В прошлом шаблоне стояло «₽ / занятие», это нужно поправить, иначе каталог будет врать в шесть раз.

**Дата начала.** У части кружков старт в октябре, у части в сентябре. Для родителя это важнее, чем номер помещения.

**Не публиковать:** номера помещений (внутренняя информация), часы нагрузки, всё содержимое листов `СВОД` и `Занятость залов`. Свод — финансовый: зачисления в ЕСЗ, план и факт по оплате.

## Слой 4: обновление

Раз в неделю или по мере правок:

1. Завуч кладёт свежий `.ods` в репозиторий (перетаскиванием в браузере).
2. GitHub Action запускает конвертер, проверяет пороги, открывает Pull Request.
3. Вы смотрите дифф: что подорожало, что исчезло, что появилось.
4. Мёрж — сайт обновился.

Пороги, при которых Action падает, а не публикует:

- кружков стало меньше 150 или больше 250
- пропал лист из списка `COURSE_SHEETS`
- у более чем 30% записей нет кода mos.ru
- в поле педагога обнаружен телефон

Последняя проверка стоит там намеренно. Сейчас телефонов в файле нет, но стоит одному человеку вписать контакт в ячейку — и он уедет в публичный доступ. Регулярное выражение в конвертере это ловит и вырезает.

## Что делать с 51 кружком без кода mos.ru

Четверть каталога останется без кнопки записи. Варианты по убыванию предпочтительности:

1. Попросить завуча дозаполнить колонку — коды у неё есть в кабинете АИС.
2. Показывать карточку без кнопки, но с телефоном приёмной.
3. Скрывать такие кружки из выдачи — плохо, каталог станет неполным.

Сюда же попадают ГПД и «Присмотр и уход» — на них запись через ПГУ и не предполагается, для них кнопка не нужна в принципе. Стоит завести признак `enrollment: "mos" | "school" | "none"`, чтобы отличать «кода нет по забывчивости» от «кода не бывает».

## Чего в решении сознательно нет

**Django, БД, админки.** 195 строк не требуют СУБД. Появится нужда — переносить будет несложно, формат `courses.json` уже нормализован.

**Форм записи.** Только ссылка на mos.ru. Своя форма делает вас оператором персональных данных со всеми обязанностями и создаёт параллельный канал записи, который не имеет юридической силы.

**Фотографий педагогов и их телефонов.** В исходном файле их нет — и не надо. Публикация ФИО с личным мобильным и фото требует отдельного письменного согласия на распространение от каждого сотрудника.

**Внешней аналитики.** Метрика и GA собирают IP посетителей. Если статистика нужна — Plausible или разбор логов.

## Порядок работ

1. Заполнить `buildings` в `config.json` реальными адресами — без этого каталог непригоден.
2. Отдать `report.txt` завучу, попросить дозаполнить коды и починить 9 битых ячеек времени.
3. Починить формат колонки «Возраст» в исходной таблице (текстовый формат).
4. Решить вопрос садов: отдельный раздел или фильтр.
5. Собрать сайт, показать завучу, собрать замечания.
6. Настроить Action и передать процесс обновления школе.
