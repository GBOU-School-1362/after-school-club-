# Развёртывание

Сайт — статика. Нужен только веб-сервер, отдающий файлы.

## Локально

```bash
uv run build_catalog.py data/catalog.ods
python3 -m http.server 8000
```

`http://localhost:8000`. Двойной щелчок по `index.html` не подойдёт: браузер запрещает `fetch` по схеме `file://`, каталог покажет сообщение об ошибке загрузки.

Если `uv` не установлен (Linux Mint, в репозиториях его нет):

```bash
curl -LsSf https://astral.sh/uv/install.sh | sh
source ~/.bashrc
```

Альтернатива без uv:

```bash
python3 -m venv .venv && source .venv/bin/activate
pip install pandas odfpy
python build_catalog.py data/catalog.ods
```

## GitHub Pages

Основной вариант. Бесплатно, без сервера, школа обновляет данные через браузер.

Settings → Pages → Source: **Deploy from a branch**, ветка `main`, папка `/ (root)`. Через минуту сайт на `https://<логин>.github.io/<репозиторий>/`.

Что учесть:

**Репозиторий должен быть публичным.** Pages из приватного репозитория требуют платного тарифа. Публичность означает, что ФИО педагогов и телефон приёмной попадут в открытый git вместе со всей историей коммитов — удалить их потом из истории сложно.

**Кеш.** `index.html` запрашивает `courses.json?v=<timestamp>`, так что обновление видно сразу. Сам `index.html` Pages отдаёт с коротким кешем, при правках вёрстки может потребоваться жёсткая перезагрузка.

**Свой домен.** Файл `CNAME` в корне с именем домена, у регистратора — A-записи на адреса GitHub Pages. HTTPS выпускается автоматически. Для кириллического домена в `CNAME` пишется punycode (`xn--...`).

## Свой сервер

Нужен, если планируется автоматическая синхронизация с mos.ru: раннеры GitHub находятся за рубежом, и запросы к московским госресурсам оттуда часто не проходят.

Caddy — потому что сам получает и продлевает сертификат:

```
kruzhki.example.ru {
    root * /srv/kruzhki
    file_server
    encode zstd gzip
    header /courses.json Cache-Control "no-cache"
    header /*.css Cache-Control "public, max-age=31536000"
}
```

Пересборка по таймеру:

```ini
# /etc/systemd/system/kruzhki.service
[Service]
Type=oneshot
WorkingDirectory=/srv/kruzhki
ExecStart=/usr/local/bin/uv run build_catalog.py data/catalog.ods --strict
```

```ini
# /etc/systemd/system/kruzhki.timer
[Timer]
OnCalendar=Mon 06:00
Persistent=true
[Install]
WantedBy=timers.target
```

`Persistent=true` важен: если сервер был выключен в понедельник, задача выполнится при следующем старте, а не пропустится.

```bash
systemctl enable --now kruzhki.timer
systemctl list-timers kruzhki
```

### Эксплуатация

Свой сервер — это обязанности, а не только возможности.

- `unattended-upgrades` включить, иначе через полгода необновлённый SSH смотрит в интернет
- `ufw allow 22,80,443`, остальное закрыто; `PasswordAuthentication no`
- бэкап `/srv/kruzhki` — файлов на пару мегабайт, достаточно копии в git
- мониторинг: после успешной сборки дёргать healthchecks.io или аналог. Без этого о сломанной синхронизации вы узнаете от родителя, записавшегося на закрытый кружок

Дата последней сборки выводится в подвале сайта. Если робот встал месяц назад, это видно любому посетителю — специально, чтобы поломка не была тихой.

## Мобильные устройства

Панель фильтров на экранах уже 640 px свёрнута в блок «Фильтры» со счётчиком выбранного; на широких раскрыта по умолчанию. Если фильтр передан в ссылке, панель открывается на любой ширине — иначе непонятно, почему показана часть каталога.

Внутри панель прокручивается и занимает не больше 44% высоты экрана, так что список кружков всегда виден. Размер нажимаемых элементов на мобильных увеличен до ~40 px.

Проверить без телефона: DevTools → Toggle device toolbar (Ctrl+Shift+M), выбрать любой узкий профиль.

## Чего на статике не будет

Форм обратной связи, счётчиков записи, личных кабинетов — всё это требует бэкенда и, что важнее, делает вас оператором персональных данных. См. [PRIVACY.md](PRIVACY.md).
